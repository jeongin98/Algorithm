### 문제 분석 요약
- 여러 개의 카드 묶음이 주어질 때, 모든 묶음을 하나로 합칠 때 드는 최소 비교 횟수를 구하는 문제이다.
두 묶음을 합칠 때 (A + B)번의 비교가 필요하고, 이 과정을 반복해 하나로 만들어야 한다.

- 즉, 합치는 순서에 따라 전체 비용이 달라지므로, 항상 “가장 작은 두 묶음부터” 합쳐야 최적해를 얻을 수 있다.

- 문제 유형:
그리디 알고리즘 + 우선순위 큐(최소 힙)

### 알고리즘 설계

#### 필요한 값

- 입력: 
    - N: 카드 묶음의 개수
    - cards: 각 묶음의 카드 수 리스트 
- 출력: 모든 묶음을 합칠 때 필요한 최소 비교 횟수

#### 풀이 순서
1. 입력받은 카드 묶음들을 최소 힙(heap) 에 저장한다.

2. 힙에서 가장 작은 두 묶음을 꺼내 합친 뒤,
    - 그 합을 결과에 더하고
    - 다시 힙에 넣는다.
3. 힙에 카드 묶음이 하나만 남을 때까지 반복한다.
4. 누적된 합계를 출력한다.

핵심 로직:
“가장 작은 두 묶음을 먼저 합친다” → 그리디 전략
“항상 최소 두 개를 빠르게 꺼낸다” → 우선순위 큐 사용

## Python (백준 표준 입력 대응)

```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n = int(input().rstrip())
    heap = []
    for _ in range(n):
        heapq.heappush(heap, int(input().rstrip()))
    
    # 묶음이 하나이면 비교가 없으므로 0
    if n == 1:
        print(0)
        return
    
    total = 0
    while len(heap) > 1:
        a = heapq.heappop(heap) # heappop()을 하면 항상 “가장 작은 원소”가 나옴
        b = heapq.heappop(heap)
        s = a + b
        total += s
        heapq.heappush(heap, s) # 우선순위큐는 가장 작은 값이 맨 앞(root)으로 오도록 재정렬됨
    print(total)

if __name__ == "__main__":
    solve()
```

### 시간 복잡도

- O(N log N)
    - 힙 삽입/삭제 연산: O(log N) 
    - 총 N개의 원소에 대해 반복 → O(N log N)
- 힙 삽입/삭제 연산이 O(log N) 인 이유:
    - 힙은 완전이진트리이기 때문에, 삽입이나 삭제 시 최대 비교 횟수가 트리 높이(log N) 만큼만 걸리기 때문


### 느낀점 or 기억할 정보
- 이 문제는 그리디 알고리즘으로 “항상 가장 작은 두 묶음을 먼저 합치면 전체 비교 횟수가 최소가 된다”는 원리를 이용한다.
- 하지만 매번 가장 작은 두 값을 빠르게 찾으려면 단순 정렬(list.sort())보다 효율적인 우선순위 큐(힙) 를 써야 한다.
- Python의 heapq는 별도의 자료형이 아니라, 기존 리스트를 힙처럼 다루게 해주는 모듈이다.
    - 그래서 heap = []로 리스트를 만들고, heapq.heappush(heap, 값) 형태로 값을 넣는 식으로 사용한다.
    - 이때 heap 리스트는 실제 데이터를 저장하는 “기반 저장소” 역할을 하며, heapq가 이 리스트를 자동으로 **“최소 힙 구조(가장 작은 값이 맨 앞에 위치)”**로 유지한다.
- 즉, heapq는 도구이고, heap 리스트는 그 도구가 관리하는 저장소다.
- heap[0]은 항상 현재 가장 작은 값이며, heappop()을 할 때마다 자동으로 다음 최소값이 앞으로 올라온다.
- 문제의 핵심은 “그리디 전략을 효율적으로 수행하기 위해 우선순위 큐를 사용하는 것” 이다.
