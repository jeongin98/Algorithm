### 문제 분석 요약
    - 지갑(wallet) 크기와 지폐(bill) 크기가 주어졌을 때, 지폐의 한쪽 변이 지갑보다 크면 긴 쪽을 반으로 접는 과정을 반복하여 지갑 안에 완전히 들어갈 때까지의 최소 접기 횟수를 구하기.
    - 지폐는 접을 때마다 한 변의 길이가 절반이 되며, 접은 뒤에는 회전(정렬)하여 더 작은 쪽부터 비교할 수 있다.
    
### 알고리즘 설계

#### 필요한 값

- 입력:
    - wallet: [가로, 세로] (지갑의 두 변 길이)
    - bill: [가로, 세로] (지폐의 두 변 길이)
- 출력: 지폐가 지갑에 완전히 들어가기까지 필요한 최소 접기 횟수 (answer)

#### 풀이 순서
1. 정렬 
    - wallet과 bill을 각각 오름차순 정렬하여 [짧은변, 긴변] 형태로 맞춤.    
    - 이렇게 하면 작은 쪽끼리, 큰 쪽끼리 비교가 가능해짐.

2. 반복문 수행 (while True로)
    - 무한 루프를 돌리되 내부에서 종료 조건을 직접 검사.

3. 종료 조건 확인
- bill[0] <= wallet[0] 그리고 bill[1] <= wallet[1]
    → 두 변이 모두 지갑보다 작거나 같으면 return answer로 종료.

4. 접기 로직
    - 아직 지갑보다 크면 긴 변을 절반으로 접음.
    - 접은 후 answer += 1, 그리고 다시 정렬.

5. 반복
    - 종료 조건을 만족할 때까지 위 과정을 반복.

## Python (백준 표준 입력 대응)

```python
def solution(wallet, bill):
    wallet = sorted(wallet)
    bill = sorted(bill)
    answer = 0

    while True:
        # 지폐가 지갑보다 작거나 같으면 종료
        if bill[0] <= wallet[0] and bill[1] <= wallet[1]:
            return answer

        # 긴 쪽을 반으로 접기
        if bill[0] > bill[1]:
            bill[0] //= 2
        else:
            bill[1] //= 2

        answer += 1
        bill = sorted(bill)  # 접은 후 다시 정렬

```

## JavaScript (Node.js, 백준 표준 입력 대응)

```javascript
function solution(wallet, bill) {
  wallet = wallet.slice().sort((a, b) => a - b);
  bill = bill.slice().sort((a, b) => a - b);
  let answer = 0;

  while (true) {
    if (bill[0] <= wallet[0] && bill[1] <= wallet[1]) {
      return answer;
    }

    if (bill[0] > bill[1]) {
      bill[0] = Math.floor(bill[0] / 2);
    } else {
      bill[1] = Math.floor(bill[1] / 2);
    }

    answer++;
    bill.sort((a, b) => a - b);
  }
}

```

### 시간 복잡도

- O(log N)
  - 지폐의 긴 변이 접힐 때마다 길이가 절반으로 줄어들기 때문에

- 참고, O(N log N)이 아닌 이유:
  - 정렬은 일반적으로 O(N log N) 이 맞으나, 이 문제에서는 “정렬 대상의 크기”가 항상 2개뿐이라는 점이 핵심이다.
  - 2개 원소를 정렬할 때는 내부적으로 “한 번의 비교”로 끝난다. 즉, sort() 한 번 = O(1)
  - 따라서 “이론적으로는 O(N log N)”이지만, N이 상수(2)인 경우엔 상수 시간 O(1) 으로 간주한다.

### 느낀점 or 기억할 정보
- 처음에는 if bill[0] < wallet[0] and bill[0] < wallet[1] and bill[1] < wallet[0] and bill[1] < wallet[1]으로 시도했는데,
이건 지폐의 두 변이 모두 지갑의 두 변 중 더 큰 쪽보다 작을 때만 종료되기 때문에, 잘못된 발상이다.
